## Outcome and review scope

Benchline coordinates a product from source-backed module research through electronics, firmware, editable mechanical CAD, application software, and verified assembly. The top canvas shows how an ESP32 accessory project could appear in the current companion shell and the proposed Benchline workspace. Both are static fixture illustrations.

This is a local, repository-owned proposal. No implementation goal is active. Start with BL-01 after reviewing its contract. The source repository is presently named KiCadCompanion; runtime branding and migration are work, not implied by the new product name.

<Callout id="authority" tone="decision">

The per-goal files in docs/benchline/goals/ are the execution contracts. docs/benchline/GOALS.md supplies shared constraints. status.json is a proposed roadmap ledger, not a scheduler and not the host's active Goal state. Editing the visual overview alone never changes a goal's acceptance criteria.

## Architecture decisions

Keep native engineering files authoritative. A versioned portable project manifest links stable IDs, requirements, relative locators, revisions, and dependency edges. User-specific mutable state stays outside portable project source.

Use local SQLite for durable tasks/attempts/evidence, with migrations and recovery. Audit the selected binding. Keep live document revision/dirty state separate from saved-file hashes. A changed input invalidates affected evidence but preserves prior history.

All Benchline-initiated actions pass through an execution boundary. Current capabilities, document identity, revision, exact arguments and approval are checked at dispatch. Allow once, Decline, and inspectable/revocable scoped Always allow are required: matching actions avoid repeat prompts but still pass fresh checks. Unknown outcomes are reconciled before retry; one native document has one writer.

Keep Codex behind a provider adapter and specialist tools behind capability adapters. FreeCAD is the first mechanical backend. Prefer permissive dependencies and retain owner review for copyleft, assets, provider terms and distribution.

A successful generated file is not a successful build; a build is not measured hardware behavior. A render is not a collision/fit test. All evidence must be linked to the relevant revisions. No goal may lower its thresholds, skip a required live test, or substitute a blocker report for required implementation.

The first implementation scope is launch/config/native/plugin identity and migration tests under BL-01. It does not include board editing, FreeCAD, publication or cutover without explicit approval.

## Boundaries and deferred work

No private customer artifacts, inherited approvals or account data are copied into Benchline. All KiCad source mutation stays on validated Konnect tools. For missing capabilities, extend and test a narrow operation under approved scope rather than bypass safeguards.

Do not publish, accept a CLA/license, purchase, flash, energize, print, deploy or perform irreversible provisioning without the required specific owner authority. Plan completion is not product release or legal clearance.

Universal routing, RF/high-speed/mains work, certification, cloud tenancy, a marketplace, broad vendor scraping, additional CAD engines and production deployment are deferred to separate future contracts.
