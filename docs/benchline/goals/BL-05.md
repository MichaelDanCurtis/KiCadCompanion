# BL-05 — Build the adaptable Benchline workspace

Status: verified under the roadmap-wide Goal. Phase: Core.
Prerequisites: BL-03, BL-04. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Deliver a responsive two-sided workspace with manual product navigation and a wide AI pane, preserving the existing companion's useful interaction patterns.

## Scope and reuse

App shell, product navigation, persisted layouts, selection/context presentation, and browser/native interaction tests. Use fixtures for not-yet-built disciplines.

Reuse first: src/main.jsx workbench/inspector/conversation; src/style.css; src/visuals.jsx; shared/visuals.mjs; src/renders.jsx; appearance and permission views.

## Deliverables

- Product navigation for requirements, modules/BOM, electronics, firmware, mechanical, app, and verification, with honest disconnected/not-supported states.
- Resizable and collapsible workspace/AI split; keyboard-accessible splitter; per-user/project persisted layout and an explicit reset.
- A detachable review/AI window with a shared selection source and controlled write ownership; native tool opening from selected artifact.

## Acceptance criteria

- [x] **BL-05-A1** — At 1024, 1440, and 1920 CSS-pixel widths and 200% zoom, selection, approvals, Stop, and the composer remain reachable without overlapping controls; narrow layouts expose a tabbed/collapsed fallback.
- [x] **BL-05-A2** — Mouse and keyboard resizing, collapse/reset, and reload preserve bounded layout preferences and do not alter project files.
- [x] **BL-05-A3** — Detached-window selection stays synchronized; reconnect does not duplicate commands, chats, or approvals; only the designated controller can submit writes.
- [x] **BL-05-A4** — Manual selection and externally observed editor changes update context; stale/dirty/disconnected state remains visible beside affected actions.
- [x] **BL-05-A5** — Existing A2UI, actual/illustrative renders, and theme choices retain their behavior. Allow once, Decline, and scoped Always allow are visible; users can inspect/revoke recurring grants and matching actions avoid repeated prompts under BL-04 safeguards. Unsupported panes are not fake working features.

## Verification

Automated browser journeys plus native two-window smoke and screenshots at the specified widths; verify state persistence and server-side denial of duplicate/stale writes.

Record each criterion in [the evidence record](../evidence/BL-05.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Native multi-window limitations require a documented supported fallback and explicit acceptance before removing the detachment criterion.

## Non-goals

No embedded reimplementation of KiCad/FreeCAD, full Figma replacement, or claim that mock UI fixtures are functioning adapters.
