# BL-04 — Enforce tool capabilities and approval boundaries

Status: verified against all five original criteria on 2026-09-09 (local date). Explicit opt-in constrained runtime, scoped native registration and shutdown ownership verified; legacy/general native mutations remain disabled. See current evidence matrix. Phase: Core.
Prerequisites: BL-02, BL-03. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Route Benchline-initiated actions through a tested execution boundary that enforces scope, freshness, consent, and outcome verification independently of agent prose.

## Scope and reuse

Proposed server/actions.mjs and server/adapters/* plus provider/tool exposure and sandbox integration. Threat model covers Benchline-controlled agents, not arbitrary same-user malware.

Reuse first: approvalScope(), approvalResponse(), ApprovalStore in server/approvals.mjs; Konnect.call()/unpack(); server/ui-mcp.mjs; server/codex.mjs; existing approval/protocol tests.

## Deliverables

- Versioned adapter contract for capabilities, observe, preview, execute, verify, cancel, and recovery inspection; explicit unsupported results.
- Two conformance implementations: fixture adapter and the existing KiCad/Konnect adapter using only currently supported operations.
- Action envelope with project/document identity, input revisions, exact action arguments, scope, idempotency key, approval decision, and outcome.

## Acceptance criteria

- [x] **BL-04-A1** — Discuss/read-only mode rejects mutations in the execution layer even when agent text requests them; direct CLI, shell, file-edit, MCP, and network bypass routes available to the agent are blocked or removed for that mode.
- [x] **BL-04-A2** — Explicit, user-visible Always allow grants cover bounded project/document/tool/action scopes. Matching operations do not re-prompt, but each operation must pass fresh revision/preview checks; changed arguments or revisions are re-evaluated against the grant, not blindly replayed. Changed identity, expanded scope, or an out-of-scope operation requires new approval; changed confirmation forms cannot silently expand grants.
- [x] **BL-04-A3** — Missing capability, wrong document, disconnected tool, stale preview, or concurrent manual edit fails before mutation.
- [x] **BL-04-A4** — Allow once is single-use; decline and immediate revocation prevent execution. Explicit recurring grants may persist only with their scope and revocation controls; unresolved approval requests cannot survive restart as automatically approved actions.
- [x] **BL-04-A5** — Partial/unknown execution is not reported as success and is not blindly retried; cancellation distinguishes stopped future work from already-applied changes.

## Verification

Negative/adversarial conformance tests with fake tools, malicious document instructions, replayed approvals, external path attempts, and a kill-between-execute-and-response fixture; approved reversible live action test on a disposable board.

Record each criterion in [the evidence record](../evidence/BL-04.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

A provider that cannot enforce the required restrictions must be disabled for that mode or reported unsupported; do not advertise enforced read-only based only on prompts.

## Non-goals

No blanket always-allow, security certification, live customer edits, automatic firmware flashing, procurement, or bypass of Konnect safeguards.
