# BL-03 — Create the versioned product-project model

Status: verified; see evidence/BL-03.md. No persistent host Goal activated. Phase: Core.
Prerequisites: BL-01. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Represent requirements, artifacts, relationships, and revisions in a durable project model that works without a PCB or agent conversation.

## Scope and reuse

Implemented shared/project.mjs and server/projects.mjs modules plus targeted index/UI wiring and tests.

Reuse first: server/config.mjs; server/index.mjs project discovery/context; RenderStore fingerprinting; Zod schemas and startup fixtures.

## Deliverables

- Versioned portable project manifest with stable project/artifact/requirement IDs and project-relative locators.
- Local mutable state store separate from the portable manifest; schema/migration documentation.
- Deterministic dependency and impact queries, with electrical, firmware, mechanical, app, and evidence artifact types.

## Acceptance criteria

- [x] **BL-03-A1** — A product can be created/opened with zero PCB files and without a signed-in agent; two projects remain isolated across reload.
- [x] **BL-03-A2** — Manifest validation rejects unsupported versions, duplicate IDs, dangling references, cycles in the declared dependency DAG, path traversal, and symlink escape.
- [x] **BL-03-A3** — Revision records identify content hashes plus live-document revision/dirty state where available; saved-file hashes are never substituted for unsaved editor state.
- [x] **BL-03-A4** — Moving a project root preserves stable identities while invalidating/rechecking execution grants and document locators.
- [x] **BL-03-A5** — A changed connector fixture identifies affected enclosure, firmware mapping, and tests without modifying any downstream artifact; unrelated artifacts remain current.

## Verification

Schema, migration, relocation, symlink and graph fixtures; restart and inspect persisted state. Include one minimal cross-discipline sample with no private customer content.

Record each criterion in [the evidence record](../evidence/BL-03.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Ambiguous source ownership must be decided before migration of real projects; synthetic fixtures can establish the schema meanwhile.

## Non-goals

No automatic cross-tool edits, cloud sync, monorepo rewrite, or replacement of KiCad/FreeCAD native file formats.
