# BL-12 — Verify the cross-discipline software workflow

Status: proposed; not activated. Phase: Integration.
Prerequisites: BL-05, BL-06, BL-08, BL-09, BL-10, BL-11. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Demonstrate one end-to-end product change across electronics, firmware, mechanical design, and frontend with revision-linked evidence and controlled recovery.

## Scope and reuse

One approved reference/pilot project with a numeric acceptance profile fixed before execution. BL-11 may be removed only by an explicit documented no-frontend scope decision.

Reuse first: All prior artifacts/adapters; original board-selection/A2UI workflow; durable tasks and dependency invalidation.

## Deliverables

- Repeatable scenario and evidence bundle from clean project open through planned change, approvals, execution, verification, and restart.
- Impact report tying a connector or module change to affected CAD features, firmware contract, frontend, BOM, and tests.
- Software-ready release manifest and a separate physical bring-up checklist.

## Acceptance criteria

- [ ] **BL-12-A1** — Baseline versions and acceptance thresholds are frozen in the scenario before changes; no lowering thresholds to make a run pass.
- [ ] **BL-12-A2** — A real connector/module revision change identifies the correct dependent tasks and leaves unrelated work untouched; user can review each change before execution.
- [ ] **BL-12-A3** — After approved changes, native KiCad and FreeCAD files reopen, firmware builds, frontend simulator tests pass, and every result references current input hashes/revisions.
- [ ] **BL-12-A4** — A mid-run restart and a manual editor change cause recovery/stale-plan handling rather than duplicate mutation or false completion.
- [ ] **BL-12-A5** — Export includes exact artifacts, tool versions, evidence, and unresolved warnings. Overall label is software-verified, with physical validation still pending.

## Verification

Run the documented full reference journey with actual KiCad/FreeCAD and pinned firmware build; browser assertions, artifact comparisons, restart fault injection, and manual inspection. Mocks cannot replace the required native integration run.

Record each criterion in [the evidence record](../evidence/BL-12.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Missing adapter/live tools, unresolved electrical/geometry requirements, or denied approvals. Report the partial evidence and exact missing gate.

## Non-goals

No manufacturing order, physical-pass claim, public release, or claim that the entire general-purpose platform is complete.

## Completion handoff

Report: criteria passed/failed/not run, evidence links, exact changed files, remaining risks, and whether the next goal's prerequisites are now met. Update the local roadmap status only with evidence. Stop after this goal; starting the next goal is the user's decision.
