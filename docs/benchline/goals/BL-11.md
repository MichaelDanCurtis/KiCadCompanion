# BL-11 — Connect an application frontend to a device simulator

Status: proposed; not activated. Phase: Disciplines.
Prerequisites: BL-04, BL-06, BL-09. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Create one working local application UI against the same versioned device protocol implemented by the firmware, with a simulator for hardware-independent verification.

## Scope and reuse

One local web frontend and device simulator in the reference project; keep the Benchline UI distinct from the product UI being generated.

Reuse first: Existing Codex App Server adapter, browser preview workflow, project artifacts, A2UI diagnostics and evidence records.

## Deliverables

- Shared protocol/schema contract and generated or validated clients for firmware and frontend.
- Live browser preview with bounded start/stop lifecycle and explicit simulator versus real-device status.
- Integration tests for commands, responses, disconnect, reconnection, invalid payloads, and version incompatibility.

## Acceptance criteria

- [ ] **BL-11-A1** — Frontend and firmware contract tests consume the same versioned schema; changing it invalidates both dependent test records.
- [ ] **BL-11-A2** — User can perform the approved reference interaction in a browser against the simulator; state is asserted, not inferred from screenshots.
- [ ] **BL-11-A3** — Disconnected, timeout, rejected-command, and incompatible-version states are visible and tested.
- [ ] **BL-11-A4** — Preview services are scoped to the selected project/local interface, do not expose secrets, and stop cleanly.
- [ ] **BL-11-A5** — Generated frontend remains an ordinary editable source project, and neither simulator behavior nor a mock dashboard is labeled device-tested.

## Verification

Browser end-to-end test plus firmware/client schema compatibility tests, process cleanup and network-binding checks.

Record each criterion in [the evidence record](../evidence/BL-11.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

The pilot must explicitly need an app. If the owner chooses no frontend, mark this branch deferred and record an approved BL-12 scope amendment rather than inventing an app.

## Non-goals

No app-store release, public hosting, cloud backend, full design-tool clone, or unverified Omni/OmniVyx dependency.
