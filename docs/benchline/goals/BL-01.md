# BL-01 — Establish the standalone Benchline foundation

Status: verified on 2026-09-05; persistent host Goal not activated. Phase: Foundation. See [current evidence](../evidence/BL-01.md). Operational cutover remains deferred; no successor goal started.
Prerequisites: none. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Run and verify Benchline from its independent checkout with explicit customer-project selection and a reversible migration path from the companion prototype.

## Scope and reuse

Standalone app source, launch/configuration, native/plugin identity, documentation, and migration tests. Inventory the customer installation read-only. Runtime cutover is a separate explicit user approval.

Reuse first: server/config.mjs configuration(); scripts/launch.mjs ready(); scripts/install-plugin.mjs; native/Companion.swift; existing startup/config/prompt tests.

## Deliverables

- Benchline branding and an independently launchable local preview; preserve old identifiers/configuration as migration inputs rather than silently overwrite them.
- Migration report naming exact old/new roots, ports, launchers, state categories, and a tested rollback procedure. Repository folder rename is optional and must not invalidate goal paths.
- Fresh-state startup and two-project isolation fixtures.

## Acceptance criteria

- [x] **BL-01-A1** — Fresh empty state launches without discovering customer boards or importing chats, renders, accounts, or approvals; no agent starts without an explicit project.
- [x] **BL-01-A2** — A port owned by another checkout/workspace is rejected. The native/plugin launcher resolves the Benchline checkout, not the customer source tree.
- [x] **BL-01-A3** — Existing tests and production build pass; live read-only smoke on an approved board confirms identity, freshness, shared selection, and saved/live labels.
- [x] **BL-01-A4** — Migration tooling defaults to dry run, excludes permission grants, and preserves original state. Until an approved cutover is performed, the report says old runtime still active and records its explicit deferred status.
- [x] **BL-01-A5** — A clean source export contains no customer files, account material, render history, or machine-specific absolute paths.

## Verification

Run npm test and npm run build; run existing startup/config fixtures; exercise a separate-port native launch and approved read-only IPC smoke. Verify files and listener identity, not just screenshots.

Record each criterion in [the evidence record](../evidence/BL-01.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Missing approved test board, incompatible local tools, active work preventing a requested cutover, or unclear state ownership. Source-only progress is not proof of a live migration.

## Non-goals

No FreeCAD integration, PCB edits, global MCP changes, publication, destructive retirement of the old app, or silent transfer of remembered permissions.
