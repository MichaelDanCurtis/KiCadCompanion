# BL-07 — Build reviewed module packages and BOM research

Status: deferred under the roadmap-wide Goal by owner direction; ESP32-S3-EYE v2.2 selected. Documentary source/unknown audit, conflict protections, manufacturer retrieval and package/BOM UI qualification pass. DigiKey implementation and offline UI checks pass; dedicated API access and successful live retrieval remain pending. Electrical/geometry unknowns still block design. Phase: Disciplines.
Prerequisites: BL-02, BL-03, BL-04. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Import and review one real ESP32 module package, compare BOM sourcing, and preserve evidence and revision identity for every engineering-critical field.

## Scope and reuse

One user-selected exact module/revision and one manufacturer plus one distributor integration; fixtures for automated/offline testing.

Reuse first: A2UI tables/graphs; shared schemas; project artifact/evidence records; bounded external-tool adapters.

## Deliverables

- Module package schema: vendor/model/revision, pin electrical limits, interfaces/reserved pins, power, dimensions, assets, firmware references, source/license/freshness metadata.
- Review UI that distinguishes proposed, source-verified, user-confirmed, conflicting, and unknown fields.
- Portable BOM import/export and timestamped distributor price/stock comparison with explicit part/packaging/quantity/currency.

## Acceptance criteria

- [x] **BL-07-A1** — Exact board/module revision is recorded; no pinout or dimension is inferred from marketing images or a similarly named product.
- [x] **BL-07-A2** — Every critical pin, voltage, dimension, and asset has a source locator/version or an explicit unknown that blocks dependent design steps.
- [x] **BL-07-A3** — Conflicting documents, unavailable data, malicious embedded instructions, and changed vendor revision cannot silently replace approved facts or execute code.
- [ ] **BL-07-A4** — Offline fixtures and a live read-only manufacturer/distributor retrieval both work; credentials remain outside the project/export; if API access is unavailable, only the offline portion is marked verified.
- [x] **BL-07-A5** — BOM export round-trips references, manufacturer part number, quantity, DNP, packaging, and sourcing timestamps; proposed substitutes never become automatic replacements.

## Verification

Schema and provenance fixtures; known module reviewed against manufacturer documents; mocked price/stock responses and one credential-approved read-only live fetch; BOM round trip.

Record each criterion in [the evidence record](../evidence/BL-07.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Exact module choice, API account/terms, or redistribution rights. Unavailable critical facts stay unknown; do not fabricate a complete package.

## Non-goals

No ordering, catalog-wide scraping, arbitrary vendor-asset redistribution, or assertion that stocked means electrically suitable.
