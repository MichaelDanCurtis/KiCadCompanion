# BL-14 — Prepare a distributable private preview candidate

Status: proposed; not activated. Phase: Release.
Prerequisites: BL-02, BL-12, BL-13. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Produce an owner-reviewable Benchline preview package with tested installation, recovery, licensing materials, and accurately bounded support claims.

## Scope and reuse

Private local packaging for the supported macOS preview. Other platforms remain separate follow-up goals until tested. Release/publication/signing-account actions require owner decisions.

Reuse first: scripts/build-native.mjs, launch/install-plugin scripts, review-check, RELEASE_REVIEW, verification reports and release evidence.

## Deliverables

- Versioned local source/binary candidate and hash manifest; dependency notices/SBOM and installation/uninstall/rollback guide.
- Fresh-user or fresh-machine installation exercise with tool discovery and explicit account/provider setup.
- Release gate report separating engineering passed, owner decisions pending, and distribution blocked.

## Acceptance criteria

- [ ] **BL-14-A1** — On the declared supported environment, fresh install opens a sample project, discovers tools, runs the approved software journey, and uninstalls without deleting customer files.
- [ ] **BL-14-A2** — Package contains no credentials, personal conversation/history, private boards, unapproved vendor assets, or inherited permissions; source and binary inputs reconcile with the SBOM.
- [ ] **BL-14-A3** — Supported tool versions, provider access/usage assumptions, failure behavior, and unsupported platforms are explicit.
- [ ] **BL-14-A4** — Recovery and rollback are exercised; security/privacy and license unknowns are surfaced with owners rather than waived by the agent.
- [ ] **BL-14-A5** — All engineering criteria have current evidence and all release decisions are presented for owner review. This goal may complete a private candidate with publication blocked; it cannot call it publicly released.

## Verification

Fresh-environment install/uninstall/rollback, candidate privacy scan, signed/hash manifest validation as available, dependency/asset reconciliation, and owner review packet.

Record each criterion in [the evidence record](../evidence/BL-14.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Missing test environment, signing credentials where required, or redistribution rights needed even for the chosen private package. A source-only report cannot satisfy an executable-package criterion.

## Non-goals

No public repository, upload, PR, app-store submission, commercial contract, trademark assertion, certification, or multi-platform support claim.

## Completion handoff

Report: criteria passed/failed/not run, evidence links, exact changed files, remaining risks, and whether the next goal's prerequisites are now met. Update the local roadmap status only with evidence. Stop after this goal; starting the next goal is the user's decision.
