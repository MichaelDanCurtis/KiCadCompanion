# BL-06 — Implement durable plan execution and evidence

Status: verified against the original criteria; see the evidence record. Phase: Core.
Prerequisites: BL-03, BL-04. Read [the shared execution contract](../GOALS.md) before starting.

## Outcome

Execute and recover a bounded dependency-based work plan across restarts, without duplicate mutations or conversational guesses about completion.

## Scope and reuse

Proposed server/workflows.mjs, durable local journal/storage, UI event projection, and restart/recovery fixtures. Choose local SQLite with migrations and transactions; audit the selected binding under BL-02 policy.

Reuse first: server/index.mjs publish(), persist(), handleAgentEvent(), chat(); server/codex.mjs; render job lifecycle and tests.

## Deliverables

- Persistent tasks, dependencies, attempts, approval references, input revisions, outputs, and evidence records.
- Explicit proposed/ready/running/awaiting-user/verifying/completed/failed/interrupted/unknown-outcome states; staleness tracked separately.
- Reconciliation on startup and single-writer execution per native document; resumable observation without replaying non-idempotent side effects.

## Acceptance criteria

- [x] **BL-06-A1** — Completion requires every acceptance item to reference current evidence; an agent's final message alone cannot complete a task.
- [x] **BL-06-A2** — Process termination at proposed, approved, executing, verifying, and post-write/pre-response boundaries preserves the journal and produces the correct recovery state.
- [x] **BL-06-A3** — Replayed events and duplicate requests do not cause duplicate writes; uncertain outcomes require observation or user reconciliation.
- [x] **BL-06-A4** — Manual edits invalidate dependent evidence; prior success remains in history but no longer counts for a changed revision.
- [x] **BL-06-A5** — Dependency cycles are rejected; failed prerequisites prevent dependent execution; independent tasks remain available; graceful shutdown drains persistence.

## Verification

Deterministic fixture DAG spanning three adapters, crash/restart matrix, stale-result tests, and a UI journey showing why each task is ready, waiting, failed, or verified.

Record each criterion in [the evidence record](../evidence/BL-06.md) using the shared template. That record is created when work starts; absence means no evidence yet. Record commands, exit codes, tool versions, input/output revisions, before/after observations, and any manual test steps. A baseline failure remains a finding, not an excuse to delete or skip a required test.

## Blockers and authority

Unknown external side effects must remain unresolved; request the minimum confirmation needed rather than retry or weaken completion criteria.

## Non-goals

No autonomous purchases, unbounded scheduling, multi-user cloud service, or claim of exactly-once behavior from non-idempotent external systems.
