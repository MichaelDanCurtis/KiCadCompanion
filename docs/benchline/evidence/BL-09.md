## Official-source boundary check and fail-closed contract validation increment

The current [Espressif ESP32-S3-EYE v2.2 guide](https://docs.espressif.com/projects/esp-board-manager/en/latest/references/boards/esp32_s3_eye.html)
was reread at the official source. Its GPIO-allocation section says all module
GPIOs are already occupied by board functions except GPIO3, and warns that
GPIO3 must be open-drain because pulling it up may damage the LED. Its revision
section identifies the v2.2 board marking and added R83 current-limiting
resistor. The extracted observations are retained in
`.runtime/bl09-official-source-check.json`; they strengthen the reserved-pin
and revision mismatch checks but do not establish a complete carrier pin map,
electrical limits or an approved behavior contract.

`shared/firmware-contract.mjs` defines the complete, owner-approved input shape
for a future offline firmware build. `validateFirmwareContract` rejects missing
or pending values, wrong target/revision, reserved-pin conflicts, unresolved
source-revision conflicts and credential-bearing fields. It reports blockers and
always returns `buildAuthorized: false` and `flashAuthorized: false`; parsing a
complete contract is validation evidence, not a build or hardware authorization.

`tests/firmware-contract.test.mjs` covers one complete synthetic contract, the
retained ESP32-S3-EYE v2.2 pending contract, target and revision mismatches,
reserved-pin conflicts, source conflicts and credential-field rejection. The
focused suite passes (5 tests). No real pin map, power limit, SDK archive or
firmware behavior was invented by this increment.

The production UI was exercised in an isolated local project. Product model →
Firmware rendered the selected ESP32-S3-EYE v2.2 target, reported the contract
as `awaiting owner inputs`, and kept **Generated**, **Built**, and
**Device-tested** as separate `not recorded` / `not run` states while listing
15 pending contract blockers. The disposable server was stopped after the
read-only journey. Receipt: `.runtime/bl09-firmware-ui-receipt.json`.
The reusable production browser fixture now asserts the same four lifecycle
labels in `tests/fixtures/workspace-browser-check.mjs`; its syntax check passes.

## Artifact hygiene increment

`inspectFirmwareArtifacts` in `shared/firmware-contract.mjs` and
`scripts/check-firmware-artifacts.mjs` provide a fail-closed pre-release scan
for future firmware source/build directories. The scan rejects credential
patterns, private-key material, machine-specific absolute paths, and artifact
locators that are not workspace-relative; an empty artifact set also fails.
`tests/firmware-artifacts.test.mjs` covers clean, rejected and empty cases, and
the CLI was exercised against a disposable clean directory followed by a
credential-bearing file. The package command is
`npm run firmware:check-artifacts -- <candidate-root>`. These checks improve
BL-09-A4 hygiene evidence but do not substitute for a pinned ESP-IDF build or
clean-room reproduction.

passes 339 tests; `npm run build` exits 0 with Vite 6.4.3;
